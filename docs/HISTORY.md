# History

The CNS pin moves, what broke and how it was fixed, and the self-hosting records.

*Moved from the README on 2026-11-10 with the text unchanged. Where it says "the README", "above" or names a section (WHAT WORKS, KNOWN DEFECTS, LIFECYCLE and so on), it means this documentation set; the map is in [README.md](../README.md).*

## MOVING BETWEEN CNS RELEASES

**Moving from CNS `v1.9.0` to `v2.0.0`.** The pin is the tag `v2.0.0`, which peels to `b13e5d2f9e0e4291725f82794b89117c3d840ac1`. Warden imports `cns.attack`, `cns.defect`, `cns.epistemic`, `cns.finding`, `cns.seat` and `cns.suite`; of those only `cns.seat.Evidence` changed (it gained `finisher_ran`, which Warden now fills). Warden does not import `cns.stack`, the one item that broke. The suite was run against the installed `cns` 2.0.0 (`direct_url.json` names `requested_revision` `v2.0.0` and that commit).

**Moving from CNS `v2.0.0` to `v2.1.0`.** The pin is now the tag `v2.1.0`, which peels to `fde931ffa89aebec95647742256ad53033bd3d02` (Warden 0.15.1). Warden's code did not change: it already checked that `Evidence` has a `ghost_severity` field before filling it, and it writes `claim` and `evidence` into the run record as extra keys, which 2.1.0 now types. The suite was run against the installed `cns` 2.1.0.

**Moving from CNS `v2.1.0` to `v2.2.0`.** The pin is now the tag `v2.2.0`, a lightweight tag, so the tag is the commit `ce6bd05578a7a3e3cafa0cfa1e9a2cca8a5f171f` (Warden 0.16.1). The `cns` package at v2.2.0 equals v2.1.0 except its version string; the release adds a composition layer beside it that Warden does not import. Warden's code did not change. The suite was run against the installed `cns` 2.2.0.

**Moving from CNS `v2.2.0` to `v2.3.0`.** On 2026-10-31 the pin became the tag `v2.3.0`, a lightweight tag, so the tag is the commit `41592fb7b6735abe140f745353c09ba3eed8e7a2`, because CNS's release table names v2.3.0 as current and the circuit installs one CNS release (`contracts/install-stack.txt` in CNS). The tested sibling set moved with it: ghost_tools, SWIZZLE, ASSAY and JUDGE are now at commits whose own `cns` pin is `v2.3.0` (the table in STACK.md), and JUDGE moved from 0.5.3 to 0.5.5, the tested set's Judge. (CNS's stack manifest, `contracts/warden-stack.json`, names a later JUDGE commit, `b20c76c`, 0.5.6, as of 2026-11-11.) Warden's code did not change. The suite was run against the installed `cns` 2.3.0 and the sibling commits in STACK.md.


## WHAT BROKE AND HOW IT WAS FIXED

Newest first, from `CHANGELOG.md`, `git log` and the tests. "Prevented by" names the test that fails if the defect comes back; "no test yet" means none exists. The CHANGELOG does not always say how a defect was found, so this section says it only where the CHANGELOG or a commit message does. Three entries (0.13.4, 0.13.6, 0.10.1) record a fix that was incomplete, reversed or described wrongly the first time.

- **1.0.0 (2026-11-13), the first release with promises.** No code differs from 0.20.0. The five criteria in `docs/RELEASE_1_0_CRITERIA_v1.md` are met: the live run outside the circuit is row 7 of `docs/REGISTRY.json` (TIE), the real Judge (the 0.6 line, JUDGE commit 0880770) read the Finisher field in that run, the stability page is `docs/STABILITY_v1.md`, seats and the target's suite run isolated by default, and tagging is the owner's step on the merge commit.
- **0.20.0 (2026-11-13), isolation is the default.** Last code change before 1.0.0. `warden tagteam` runs the named seats and the target's pytest suite closed in by the operating system unless `--no-isolation` is given; `--isolate-seats` is still accepted and the two cannot be given together. Where the limits cannot be given the run is refused, so such a machine, and a Rust target, need `--no-isolation`, which writes a warning into the record's notes. The test suite turns the default off for tests about something else (`tests/conftest.py`), and `tests/test_isolation_default.py` holds the shipped value. Prevented by `tests/test_isolation_default.py`.
- **0.19.0 (2026-11-12), the target's own pytest suite can run confined.** Last part of 1.0.0 criterion 5. With `--isolate-seats` the suite runs on the real tree with no network, writing only to a scratch folder and three named cache folders; a suite that needs more goes red with the reason, never passes. Cargo suites are refused in this mode. Prevented by `tests/test_isolated_seat.py`.
- **0.18.0 (2026-11-12), the Drafter and the Finisher can run in their own confined programs.** Second slice of 1.0.0 criterion 5. `--isolate-seats` now covers every named seat except the claim seat. A seat's `scope` and `describe_skipped` are carried across the boundary, so Warden's `hasattr` and `getattr` checks answer as they do for the seat itself. Prevented by `tests/test_isolated_seat.py`. The target's own suite is not yet confined.
- **0.17.0 (2026-11-12), the Judge can run in its own confined program.** First slice of 1.0.0 criterion 5 (`docs/RELEASE_1_0_CRITERIA_v1.md`). `--isolate-seats` starts the Judge as a separate process, closed in by Landlock, seccomp and size limits before any seat code is imported, talking to Warden in plain messages. It closes, for the Judge only, the limit that a seat could change Warden's own objects in memory. Prevented by `tests/test_isolated_seat.py`. The Drafter, the Finisher and the target's suite are not yet isolated.
- **0.16.6 (2026-11-11), a `git replace` ref defeated the pin check, the dirty check and the claim read.** Found by an independent review and reproduced: `git replace <pin> <new>` then `git checkout <pin>` made a checkout report the pinned commit and a clean status while holding other content, and a claimed commit read through a replace ref gave another commit's bytes under the first SHA. Every git call now runs with `GIT_NO_REPLACE_OBJECTS=1` set in one place (`warden/gitstate.py::_env`). Prevented by `tests/test_replace_refs.py`. Grafts (`.git/info/grafts`) are not honoured by current git; that was not separately tested.
- **0.16.5 (2026-11-04), a manifest that omitted WARDEN was accepted with a dirty WARDEN checkout.** Found by the round-8 red team: a `--stack-manifest` or `--cns` manifest that left out `warden` ended exit 0 with a modified `warden` checkout in the folder, while a manifest that left out `ghost_tools`, `swizzle`, `assay` or `judge` was refused. Closed by owner decision (2026-11-04): all five circuit members must be named, and an omission is a usage error naming the member. The earlier refusal for the other four applied only to the folders the run used, so an explicit `--swizzle-root` with a manifest omitting `swizzle` was accepted; that is refused too. Prevented by `tests/test_stack_roster.py::test_a_manifest_that_omits_warden_with_a_dirty_checkout_is_refused_naming_warden`.
- **0.16.4 (2026-10-30), the claim row named bytes that did not land.** Found by the round-8 audit and reproduced: writes preserved a pure-CRLF file's line endings, so a claimed commit that turned CRLF into LF left the file CRLF on disk while `claim.files[].after_sha256` reported the commit's blob and the run ended `ACCEPT`. The claim seat now writes the claimed bytes exactly and the row's digest is that of the landed bytes; a mismatch refuses the run. A claimed commit that only changed line endings was also skipped as "nothing to propose"; it is applied now. Prevented by `tests/test_claim_landed.py::test_a_commit_that_turns_crlf_into_lf_does_not_leave_the_file_crlf` and `::test_a_landed_digest_that_differs_from_the_claimed_blob_refuses_the_run_and_puts_everything_back`.
- **0.16.4, a held deletion of an executable file left the tree dirty.** Found by the round-8 audit: the snapshot restore gave a deleted executable back as mode 644, so `git status` showed `M run.sh` and `warden keep` was refused. Prevented by `tests/test_executable_restore.py::test_a_held_claimed_deletion_of_an_executable_leaves_a_clean_tree_and_keep_succeeds`.
- **0.16.4, credentials leaked into the record.** Found by the round-8 audit: `origin_of` recorded the raw remote URL, so `https://user:token@host/...` reached `claim.origin`, the held file, the receipt and the chronicle file name and lines. Prevented by `tests/test_origin_secret.py::test_no_output_of_a_run_holds_the_secret`.
- **0.16.4, `warden chronicle DIR` gave a traceback or skipped lines.** Found by the round-8 audit. The 0.16.3 entry below says a damaged chronicle is refused; that covered `warden tagteam --chronicle` only, and the reader command still failed this way until 0.16.4. Prevented by `tests/test_chronicle_reader.py::test_a_file_that_is_not_utf8_is_exit_2_naming_the_file` and `::test_a_bad_line_is_exit_2_naming_the_file_and_the_line`.
- **0.16.4, a claim could change a link's target, and a pipe as the claim diff blocked forever.** Found by the round-8 audit: a `--claim-diff` naming `inlink.py` (a link to `pkg/__init__.py`) changed the target of the link, and `--claim-diff FIFO` never returned. Prevented by `tests/test_claim_paths.py::test_a_diff_naming_a_path_through_a_link_is_refused_and_nothing_changes` and `::test_a_fifo_as_the_claim_diff_is_exit_2_not_a_hang`.
- **0.16.4, a tree with a non-UTF-8 file name ended the run as ERROR.** Found by the round-8 audit: `_fingerprint` raised `UnicodeEncodeError`. Prevented by `tests/test_fingerprint_names.py::test_a_tree_with_a_non_utf8_file_name_fingerprints`.
- **0.16.4, the help said the target must stand at the parent, but only the touched files were compared.** Found by the round-8 audit. The claim row now records `target_tree_digest` and `base_matches_parent` (no new refusal), and the help and README say what is compared. Prevented by `tests/test_claim_base_honesty.py::test_a_target_that_differs_elsewhere_is_still_accepted_and_the_row_says_false`.
- **0.16.4, stale text.** The README said "all seven live" and listed six, said the quickstart was run "as written" without a version, said suite reuse never reaches across runs beside the opt-in that does, and described renames and quoted paths without saying which way of naming a change refuses them. No test.
- **0.16.3 (2026-10-30), a claimed mode change was not refused.** Found by the round-7 audit (static reads): the README and CHANGELOG promised that a mode change is refused, but a commit whose only change was a mode (`git status` M, identical blobs, 100644 to 100755) was read as a write of the same text and went through, and a `new file mode 100755` file in a `--claim-diff` was written without the executable bit. Both are refused now, with the path and both modes. Prevented by `tests/test_claim_seat.py::test_a_commit_whose_only_change_is_a_mode_change_is_refused_naming_the_path_and_both_modes` and `test_a_diff_file_that_adds_an_executable_file_is_refused`.
- **0.16.3 (2026-10-30), the tree fingerprint could collide.** Found by the round-7 audit: `_fingerprint` hashed each path and then its bytes with no delimiter, so `a` holding `bc` and `ab` holding `c` hashed the same, and so did a boundary shift between two files; the executable bit was not hashed. The hash now covers the entry count and each length-prefixed path, executable bit and length-prefixed bytes. Prevented by `tests/test_fingerprint.py`.
- **0.16.3 (2026-10-30), a damaged chronicle gave a traceback or was silently skipped.** Found by the round-7 audit: `chronicle.read` raised on a file that is not UTF-8 (a traceback) and skipped a line that is not JSON without a word. Both now refuse the run with exit 2, naming the file and line. The chronicle stays an unsigned plain file; no tamper detection was added. Prevented by `tests/test_chronicle.py::test_a_run_with_a_chronicle_that_has_a_bad_line_is_refused_with_exit_2` and `test_a_run_with_a_chronicle_that_is_not_utf8_is_refused_with_exit_2`.
- **0.16.2 (2026-10-30), a folder holding a seat the manifest omits was accepted when an option supplied the seat.** Found by the Stage 2 run: with a manifest that omits `drafter`, a `--stack` folder that still held a drafter checkout was refused on a bare `--stack` but accepted with `--claim-commit`, `--claim-diff` or `--drafter` (and the same for `burnish` with `--finisher`), although the text above says it is refused. The folder was compared with the manifest only for a seat whose option was still unset, and those options had already set it. Now the comparison is made before any option is substituted. A manifest that is not one this Warden accepts (wrong schema or contract, or no repositories) is treated as no manifest for this comparison, so its own problem is the one reported. The governed target itself is not counted as a held seat, as everywhere else. Prevented by `tests/test_stack_released.py::test_a_drafter_checkout_the_manifest_omits_is_refused_whatever_option_supplies_the_seat` and `::test_a_burnish_checkout_the_manifest_omits_is_refused_with_an_explicit_finisher`.
