## WHAT WORKS

Each line names the test, the CI job or the recorded run that shows it. A test file named here means the tests in it pass in CI. The CI jobs are in `.github/workflows/tests.yml`: `lint` (`ruff check .` and `mypy`), `extras` (the `ghost` extra installs and `pip check` is clean), `pytest` (one job each for Python 3.11, 3.12 and 3.13, with a skipped test counted as a failure), `circuit` (the smoke test against live siblings and the real Judge) and `assay-latest` (non-blocking: it takes ASSAY at its newest commit to show drift and gates nothing). The run for any head is on the repository's Actions page, and the last checked runs are listed in the CNS repository's `docs/STATUS.md`.

- The claim seat (`--claim-commit SHA`, with `--claim-repo PATH` when the target does not hold the commit, or `--claim-diff FILE` with `--claim-subject` and `--claim-author`) takes the Drafter seat with a real change, proposes it once and then nothing, and carries commit, parent, tree, the diff's sha256 and size and each file's sha256 before and after as evidence. A binary file, a symbolic link or submodule in the commit, a mode change, a claimed path that is or lies below a link in the target, and a touched file that differs from the parent are refused with a reason before anything runs (exit 2); `--claim-*` beside `--drafter` is a usage error. Renames and quoted paths depend on how the change is named: a `--claim-commit` rename is read as a delete plus an add, applied, and (because it deletes) ends held for a named human; a `--claim-diff` rename or copy header is refused (exit 2); a path git quotes (its default for unicode and newline names) is refused by `--claim-diff` only, because `--claim-commit` reads paths NUL-separated. The rest of the tree is not compared: the touched files must match the parent, and the row's `base_matches_parent` says whether the whole tree did. **VERIFIED** by `tests/test_claim_seat.py`.
- Every record carries a claim row (`claim`): origin, base and claimed commits and tree digests, subject, author, date, the diff's sha256 and size, the files by sha256 before and after with a `protected` flag, actor, authority, authorization and transformation ids, scope, the structured suite results, Ghost's counts, new and closed findings, the Judge's sentences (`rules_fired`), the Judge seat and verdict, decision, held digest, held tree digest, participants, the Finisher's edits by file apart from the actor's, `target_tree_digest` (the fingerprint of the target before the run, the same value as `base_tree_digest`) and `base_matches_parent` (true iff that equals the fingerprint of the claimed commit's parent tree materialised from the claimed repository, false otherwise, null when it cannot be computed, as for a `--claim-diff`; record only, nothing is refused on it, held by `tests/test_claim_base_honesty.py`); the Judge's whole `Evidence` rides beside it (`evidence`), and both are in the held file and the receipt. From the row alone a reader names the governed commit (its `diff_sha256` matches exactly one of a set of candidate commits) and sees the held tree as base plus the claimed diff plus the Finisher's edits, file by file and by fingerprint; the row round-trips through JSON. An ordinary Drafter run has a row with `claimed_commit` null and its files from the Transformation. **VERIFIED** by `tests/test_claim_row.py`.

- The chronicle (`--chronicle DIR`) appends one line per run to `DIR/<origin slug>.jsonl`, keyed by origin, base commit and claimed commit, with the promises the run opens if kept; a later run whose base tree is an earlier run's claimed or held tree settles those promises (HELD or BROKEN, with the measurement) and writes the settlement into its own line and its record's notes; `warden keep --chronicle DIR` appends who kept which digest and when; `warden chronicle DIR [--origin X]` prints the chain in order. - Opt-in suite reuse across runs, keyed by the chronicle: with `--chronicle DIR --reuse-chronicle-suite`, the first suite pass ("cycle 1 before") takes the result an earlier run's line recorded for this run's base tree (that line's claimed or held tree digest equals the base tree digest) when the result is green (no failures, no errors, a pass, exit status 0, recorded green) and the environment key is equal on every field (Python version, pytest version, Warden version, platform, suite runner, suite command); the record's `suite_passes` and the row's `suite_before` say `reused_from` `chronicle:<run id>`, and a note says "suite pass cycle 1 before: reused the result of chronicle run <id>, tree digest <d> identical". Otherwise the suite is run, and a note says no line matched. A result taken from the chronicle does not settle the chronicle's own `suite_green` promise (it stays OPEN).
